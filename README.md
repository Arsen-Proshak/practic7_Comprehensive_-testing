# Практична робота № 6–7: Проєктування станів екрана, дизайн-токени та QA-аудит веб-додатку

## Опис проєкту
Інтерактивний веб-додаток «Каталог навчальних модулів», реалізований на чистому JavaScript (ES6+) та нативних CSS Custom Properties без сторонніх фреймворків[cite: 1, 3]. Проєкт демонструє життєвий цикл станів інтерфейсу (`Loading`, `Content`, `Empty`, `Error`), трирівневу систему дизайн-токенів (`Primitive`, `Semantic`, `Component`), підтримку світлої/темної тем та комплексний інженерний аудит якості[cite: 1, 3].

## Аудит адаптивності та Chrome DevTools Lighthouse

### 1. Перевірка адаптивності (Responsive Testing)
* **375 px (Mobile):** картки шикуються в 1 колонку, елементи панелі керування переносяться без накладання, горизонтальна прокрутка відсутня[cite: 3].
* **768 px (Tablet):** сітка адаптується у 2 колонки, поля форми вирівнюються коректно[cite: 3].
* **1440 px (Desktop):** контент центрується у контейнері `960px` із сіткою у 3 колонки[cite: 3].

### 2. Результати автоматизованого аудиту (Lighthouse — Desktop)
* **Accessibility:** `92 / 100` (наявні прив'язані `<label>`, семантичні `<button>` та коректні `aria-*` атрибути[cite: 3, 4]; виявлено незначні зауваження щодо контрастності бейджів та порядку заголовків `h3`–`h4` у секції UI-Kit[cite: 4]).
* **Best Practices:** `100 / 100` (відсутні помилки в консолі, безпечна маніпуляція DOM без `innerHTML`, коректний `DOCTYPE` та кодування)[cite: 3, 4].
* **SEO:** `100 / 100` (наявні `<title>`, `<meta name="description">`, `<meta name="viewport">` та семантична ієрархія заголовків)[cite: 3, 4].

## Модульні перевірки (Native Unit Assertions)
У файлі `tests.js` реалізовано набір ізольованих модульних перевірок за допомогою вбудованого методу `console.assert()`, які верифікують чисті функції `validateInput()`, `isValidState()` та `filterModulesList()` під час завантаження сторінки без побічних ефектів у DOM[cite: 3].
